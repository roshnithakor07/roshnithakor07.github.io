ESDL Dashboard

Real-time KPIs and threat views over hundreds of millions of records for power-grid security.

Real-time KPIs over hundreds of millions of records · MongoDB → ClickHouse · no hardware scale-up

  • Next.js
  • ClickHouse
  • ECharts

Deep dive ⌄

The problem

Customers depended on external tools like Trend Micro. The goal was one dashboard where clients see their advisories, security alerts, threat data and KPI metrics in real time.

What I built

  • Full stack: NestJS backend APIs, a Next.js + TypeScript frontend and Apache ECharts visualisations.
  • Real-time KPI widgets for active alerts, threat counts and resolved incidents.
  • Search over security data with date ranges and Lucene queries against OpenSearch.

The hard part

Hundreds of millions of records without timeouts

Some searches touched hundreds of millions of records, so the backend timed out and the dashboard froze. I rewrote the pagination logic, pushed heavy computation into MongoDB aggregation pipelines so the database did the work, and added Redis caching for frequently requested data. As a team we then moved the analytics workloads from MongoDB to ClickHouse, and I optimised the ClickHouse queries for real-time security events, cutting query times well below MongoDB’s.

The result

The dashboard became faster, more responsive and scalable, and customers could monitor security data in real time without leaning on external tools.

Health Check Automation

27 dynamic charts and 30+ page DOCX/PDF reports generated from raw Excel exports.

16–20 hours → under 1 hour per report · 27 charts · adopted by the whole team

  • MERN
  • SheetJS
  • Chart.js
Deep dive ⌄

The problem

The customer success team spent 16 to 20 hours preparing each client health-check report by hand: copying data, building charts one by one, formatting documents.

What I built

  • A full-stack Node.js and React app: upload an Excel file, the data is processed, 27 charts are generated and a fully formatted report is exported as both PDF and Word.
  • A dashboard to view reports and analytics, with create, update and delete for reports.
  • Role-based access for Developer, Root User, Health Check User and Viewer, each with different permissions.
  • Security headers, rate limiting, input sanitisation and two-factor authentication with time-bound OTPs.
  • A global error-handling middleware that catches unexpected errors gracefully.

The hard part

Blank charts in the exported PDF

All 27 charts rendered asynchronously, so the PDF could be generated before they finished and come out with blank charts. I used Promises to wait for every chart to finish rendering before starting the PDF export.

The result

Once deployed, the same report was ready in under an hour, and the customer success team adopted the tool completely.

Trade-off

The app was I/O-heavy with low traffic, so reports were generated in the request. With heavier reports or many concurrent users, I would move generation to a job queue.

Support Desk

Ticketing with role-based access and agent teams, SLA tracking with automatic breach alerts, merge and bulk actions, and a full activity log; 40 product rules, each proven by tests.

40 product rules · 132 tests · SLA breach alerts · video walkthrough

  • React
  • Node.js
  • Express
  • MongoDB
  • JWT
Deep dive ⌄

The problem

Support tools go wrong in the details: tickets that skip steps, SLA clocks that quietly reset, and agents who can grab work outside their team. Every rule had to hold, not just the happy path.

What I built

  • 40 product rules enforced in the service layer, each with its own error code (for example 409 INVALID_TRANSITION) and its own test.
  • A ticket lifecycle that moves one step at a time, with a 14-day reopen window; resolving needs a public reply from the team.
  • Agent teams: access is decided twice, by role and by category, and new tickets go to the least-loaded agent who covers them.
  • Merge, bulk actions, canned responses, a full activity log, in-app notifications and an analytics dashboard.
  • Rate-limited sign-in, and signed-out tokens stored as hashes that expire on their own, so a restart never undoes a sign-out.

The hard part

An SLA clock you can trust

The deadline moves only on a reopen or a priority change on a live ticket, and a breach is permanent. A sweep runs every minute, flags overdue tickets as the system (not a person) and tells every admin; if a sweep is still running when the next is due, the next one is skipped, never doubled.

The result

40 rules, each proven by tests (132 in total), plus a video walkthrough of the customer, agent and admin flows.
